# WEB-334 FAQ Section Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Editors maintain FAQ documents in the studio, each department page shows its FAQ as an accordion between stats and contact persons, and a question is marked up as `FAQPage` JSON-LD on the page of its first department only.

**Architecture:** A new `faq` document type references `department` documents. `departmentPageQuery` returns the department's FAQ (filtered on `departments`, not `references()`), with `answerText` from `pt::text()` and `isMarkedUp` for the first department. The page renders a server `Faq` section on a new Base UI accordion wrapper and a `JsonLd` built by `getFaqPageSchema`, which keeps only complete, marked-up questions.

**Tech Stack:** Sanity Studio 6 (`defineType`, structure builder, presentation tool), Next.js 16 App Router with `sanityFetch`, `@base-ui/react/accordion`, `schema-dts`, Vitest via `vp test`, Playwright with recorded fixtures.

**Spec:** `docs/superpowers/specs/2026-10-25-web-334-faq-design.md`

## Global Constraints

- Studio titles and descriptions are German; code, comments, tests and the English docs (`AGENTS.md`, `docs/SANITY_WEBHOOK_SETUP.md`) stay English.
- `defineType` / `defineField` / `defineArrayMember` from `sanity`; icons from `react-icons/ri`; GROQ through `defineQuery`; fragments interpolated from `@/lib/sanity/queries`.
- After a schema or query change run from the repository root: `pnpm run extract-types && pnpm run typegen:sanity`, then `pnpm exec vp fmt apps/studio/schema.json` (the extract is written unformatted).
- The agent shell lacks Node on `PATH`: prefix every `pnpm`, `node` or `vp` command with `export PATH="$HOME/.local/share/vite-plus/bin:$PATH";`.
- Tests sit next to their source and import from `vite-plus/test`; assert what a user observes (role, name, text, attribute), never a class or `data-testid`.
- No `try`/`catch`/`finally` in components or hooks.
- Fallback heading copy: title „Häufige Fragen“, subtitle „FAQ“, no intro.
- Never write to the `production` dataset. `apps/studio/.env` points at `production`, so every dataset write names `development` explicitly, and every write needs the user's OK first.
- Commits: `pnpm run format:check` at the root first, then `but commit -b feat/web-334-faq-section -m "<conventional message>"`; no `Co-Authored-By` or generator lines.

## Review Focus

- An answer that links to a department through an `internalLink` must not put the FAQ on that department's page; only `departments` decides (Task 5 pins the filter).
- A draft FAQ without a question or with an empty or whitespace-only answer shows neither in the section nor in the JSON-LD (Tasks 3 and 5).
- A department whose FAQ all belong first to another department shows the section but no `FAQPage` (Task 6).
- In draft mode the JSON-LD carries no stega characters, while the section keeps them for click-to-edit (Task 6).
- `groupsPage` without `faqSection` (production until the editors fill it) shows the fallback heading (Task 5).
